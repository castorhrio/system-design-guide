前置知识清单

读这套笔记之前，你需要具备哪些基础。不需要精通，但需要"知道有这么回事"。

这份清单按重要性排序。前两节是硬性要求——缺了会读不下去；后面几节可以边读边补。

每一项都给了自测问题。如果你能答上来，就跳过；答不上来，先补那一条。

一、网络基础（硬性要求）

系统设计本质上是在设计"网络上的多台机器怎么协作"，所以网络是第一基础。

1.1 HTTP 与 HTTPS

需要懂到什么程度：

  • HTTP 请求/响应的结构（方法、状态码、头部、正文）
  • 常见状态码的含义：200 / 301 / 302 / 400 / 401 / 403 / 404 / 429 / 500 / 502 / 503
  • 无状态（stateless）的含义
  • HTTPS 做了什么（TLS 握手、证书、加密）

自测：

  • 301 和 302 有什么区别？为什么短链系统选哪个会影响统计能力？（见第 8 章）
  • 429 表示什么？应该配合哪个响应头告诉客户端多久后重试？（见第 4 章）
  • 为什么说 HTTP 是无状态协议？这和"无状态 Web 层"是同一件事吗？

1.2 TCP 与 UDP

需要懂到什么程度：

  • TCP 提供可靠、有序、面向连接的传输；UDP 不保证
  • 三次握手、四次挥手的大致过程
  • 为什么 TCP 有队头阻塞问题

自测：

  • 为什么行情推送可以用 UDP，订单提交必须用 TCP？（见第 28 章）
  • WebSocket 建立在 TCP 还是 UDP 之上？

1.3 DNS

需要懂到什么程度：

  • DNS 把域名解析成 IP
  • 有缓存，且分层解析
  • 可以通过 DNS 做流量调度

自测：

  • GeoDNS 是怎么把用户导向最近的数据中心的？（见第 1 章、第 18 章）

1.4 延迟的物理直觉

需要懂到什么程度：知道"不同层级的操作差几个数量级"。

操作 量级
内存随机访问 100 纳秒
SSD 随机读 20–100 微秒
同机房网络往返 0.5 毫秒
磁盘寻道 2–10 毫秒
跨大洲网络往返 100–200 毫秒

自测：

  • 从北京访问美国西海岸的服务器，光速决定的物理下限是多少毫秒？
  • 为什么"把内容放到 CDN 边缘节点"能快那么多？（见第 1 章）

详细数字见第 2 章，那里给出了更新后的版本。

二、数据库基础（硬性要求）

后面至少 15 章会涉及数据库，这是第二个硬基础。

2.1 索引

需要懂到什么程度：

  • 索引是用额外空间换查询速度
  • B+ 树索引的结构（为什么适合范围查询）
  • 索引会拖慢写入（每次写都要维护索引）

自测：

  • 为什么 ORDER BY score DESC LIMIT 10 在 score 有索引时很快，但在需要"求某人排名"时很慢？（见第 25 章）
  • 为什么随机生成的 UUID 做主键会拖慢 InnoDB 插入？（见第 7 章）

2.2 事务与隔离级别

需要懂到什么程度：

  • ACID 分别是什么
  • 四种隔离级别，以及各自能防止什么问题（脏读、不可重复读、幻读）
  • 行锁与表锁

自测：

  • "先 SELECT 查库存，再 UPDATE 扣减"为什么在并发下会超卖？正确写法是什么？（见第 22 章）
  • 乐观锁和悲观锁分别适合什么场景？

2.3 复制与分片

需要懂到什么程度：

  • 主库写、从库读的基本模型
  • 复制有同步/异步之分，异步复制会丢数据
  • 分片是把数据按某个键拆到多台机器

自测：

  • 为什么"主库挂了直接提升从库"可能导致数据丢失？（见第 1 章、第 15 章）

2.4 SQL 与 NoSQL 的取舍

需要懂到什么程度：

  • 关系型数据库强在事务、JOIN、复杂查询
  • NoSQL 放弃部分能力换取水平扩展
  • 默认选关系型，除非有明确理由

自测：

  • 什么情况下应该用 NoSQL？给出三个具体理由。（见第 1 章）

三、操作系统与并发（建议先了解）

3.1 进程、线程与并发

需要懂到什么程度：

  • 进程有独立内存空间，线程共享
  • 竞态条件（race condition）是怎么产生的
  • 锁的作用和代价

自测：

  • 两个请求同时给同一个账户扣款 100 元，余额从 200 变成 100 而不是 0，为什么？
  • 单线程的 Redis 为什么能支持高并发？（提示：不是靠多线程）

3.2 I/O 模型

需要懂到什么程度：

  • 阻塞 I/O 与非阻塞 I/O 的区别
  • 什么是零拷贝（zero-copy）

自测：

  • Kafka 用磁盘为什么还这么快？零拷贝在这里起什么作用？（见第 19 章）
  • 为什么说"消息队列存在内存中"是错的？（见第 1 章）

3.3 内存与缓存

需要懂到什么程度：

  • 内存比磁盘快几个数量级
  • 操作系统页缓存（page cache）的存在

自测：

  • 为什么"写磁盘"的操作实际上大部分是写内存？（提示：页缓存）

四、编程与数据结构（建议先了解）

4.1 基础数据结构

需要懂到什么程度：

  • 哈希表：O(1) 查找，但不维护顺序
  • 跳表 / 红黑树：O(log N) 查找，维护顺序
  • 堆、队列、栈

自测：

  • 排行榜为什么用 Redis 的 Sorted Set 而不是哈希表？（见第 25 章）
  • 订单簿为什么需要有序索引，普通哈希表为什么不行？（见第 28 章）

4.2 概率与估算

需要懂到什么程度：

  • 能心算量级（10^3、10^6、10^9 分别是什么规模）
  • 理解生日悖论（为什么碰撞比直觉来得早）

自测：

  • 1 天大约等于多少秒？（面试常用换算：约 10^5 秒）
  • 62 个字符组成 7 位短码，能表示多少个 URL？（见第 8 章）

4.3 序列化

需要懂到什么程度：知道 JSON、Protobuf、Avro 的大致区别和用途。

六、如果你时间有限，优先补这三样

  1. HTTP 状态码 + TCP/UDP 的区别（半天）
  2. 数据库索引 + 事务隔离级别 + 乐观/悲观锁（一天）
  3. 量级估算的心算能力（一小时）

这三样补齐，28 章就能顺利读下去。剩下的可以边读边查术语表。

七、不要做的事

不要为了"准备好"而无限期推迟开始。

系统设计这门学问的特点是：很多概念必须在具体问题里才能真正理解。你不需要先学完分布式理论再来读第 6 章——恰恰相反，读完第 6 章你才会明白 CAP 到底在说什么。

正确的做法是：先读，卡住了再回头补。这份清单是给你"卡住时查"用的，不是"开始前的门槛"。
